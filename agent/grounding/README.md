# Grounding data

What the agent's tools (`lookup_vocab`, `lookup_verb`, `lookup_grammar`,
`check_register`) read at runtime instead of trusting the model's own
memory of Romanian.

## vocab.json, grammar.json

Generated by `python tools/extract_grounding.py`, which parses `VOCAB` and
`GRAMMAR_TOPICS` straight out of `js/data/*.js` using `tools/_jslit.py` (a
small recursive-descent parser for the JS-object-literal subset those files
use. Regex alone isn't safe here once you hit nested `ex:{ro,en}` and
`formation:[...]` arrays full of HTML tags and apostrophes).

`check_register` has no dataset of its own: register is just a field on
vocab entries (`register:"informal — slang"` etc.), so it queries
`vocab.json` directly.

Re-run after any edit to `VOCAB` or `GRAMMAR_TOPICS`, the same way
`check_content.py` needs re-running after a content edit.

## verbs.json

**Not** produced by parsing `verbs.js` in Python. Deliberately: this project's
conjugation engine (`verbTables()` in `js/features/conjugation.js`) generates
regular forms from the infinitive and only stores hand-authored tables for
irregular verbs. Re-deriving those rules a second time in Python risks the
exact class of bug already recorded in the main CLAUDE.md ("the engine once
invented `zici!`, `pui!` and `deschizi!`"). So `verbs.json` is the real
engine's own output, captured once by running this in the browser console
against the app served locally (`python tools/serve.py`):

```js
VERBS.map(function(v){
  var t = verbTables(v);
  return {
    id: v.id, inf: v.inf, en: v.en,
    group: verbGroupKey(v), irregular: !!v.irregular,
    notes: v.notes || null,
    example: v.example || null,
    present: t.present, past: t.past, imperfect: t.imperfect,
    future: t.future, conditional: t.conditional, subjunctive: t.subjunctive,
    imperative: t.imperative, participle: t.participle
  };
});
```

Re-capture the same way if `VERBS` in `js/data/verbs.js` changes (a verb
added, an `irr` override edited, a class retagged).
